# LawMind 业务流程说明

## 1. 客户咨询流程

```text
客户进入 /
  -> 输入法律问题
  -> 系统识别法律领域
  -> 提取实体与风险信号
  -> 判断是否检索知识库
  -> 4 类 Agent 路由
  -> Agent 调用法律工具
  -> 生成初步分析与缺失事实
  -> 展示律师推荐
  -> 支持预约律师 / 转人工 / 留资
```

### 场景一：醉驾/危险驾驶

```text
用户：喝酒开车被交警查到，会怎么样？

系统：
  intent = dangerous_driving
  risk_flags = 可能包含 traffic_accident / detention
  检索：血液酒精含量、危险驾驶罪、立案标准
  Agent：CriminalDefenseAgent
  提示：需补充酒精含量、是否事故、是否已立案/拘留
  下一步：可留资或转人工
```

### 场景二：刑事拘留

```text
用户：家人被刑事拘留了

系统：
  intent = criminal_defense
  risk_flag = detention
  路由：EscalationAgent
  回复：整理已知信息、告知尽快联系执业律师/人工客服
  输出：escalated = true
```

### 场景三：民事纠纷

```text
用户：公司拖欠工资，怎么办？

系统：
  intent = labor_dispute
  Agent：CivilConsultationAgent
  工具：extract_civil_facts / determine_procedure / assess_civil_risk
  返回：证据材料、仲裁/诉讼路径、风险提示
```

### 场景四：预约律师 / 转人工

```text
用户：我想预约律师，麻烦人工联系我

系统：
  intent = lawyer_appointment
  路由：EscalationAgent
  输出：escalated = true
  引导：填写姓名、手机号、城市、联系时间
  提交：POST /api/law/transfer
  数据库：source = transfer
```

## 2. 什么时候转人工

以下情况会触发转人工：

- 用户明确说“转人工”“预约律师”
- 紧急度 `CRITICAL`
- 风险标记 `DETENTION`
- 风险标记 `COURT_SOON`
- 用户提供的信息包含重大人身伤害或危急情形
- 多次无法判断法律领域
- 用户明确要求人工介入

触发后：

- 内部：`OrchestratorResult.escalated = True`
- 对外：`LawChatPublicResponse.escalated = True`
- 建议前端：展示“转人工”提示
- 客户提交：`/api/law/transfer`
- 工作人员页：查看 `source = transfer` 的记录

## 3. 知识库更新流程

```text
工作人员在 /staff 新增/编辑 FAQ
  -> POST /api/law/admin/faqs
  -> PostgreSQL law_faq
  -> sync_status = pending
  -> FaqSyncService 同步到 ChromaDB law_knowledge_base
  -> sync_status = synced / failed
```

也可以点击“知识库同步”：

```text
POST /api/law/admin/knowledge/reload
```

## 4. 工作人员流程

```text
打开 /staff
  -> 输入管理员密码
  -> 查看咨询记录
  -> 更新状态 PENDING / CONTACTED / BOOKED / CLOSED
  -> 管理律师
  -> 管理 FAQ
  -> 查看指标
  -> 触发知识库同步
```

## 5. 评测流程

```text
POST /eval/run
  -> 输入评测用例
  -> 意图评测
  -> 端到端调用 AgentOrchestrator
  -> LLM-as-Judge 评分
  -> 与归档基线对比
  -> 输出通过率、回归和建议
```

## 6. 当前业务边界

- 只支持中国大陆法律语境。
- AI 仅提供一般法律信息，不构成正式法律意见。
- 当前不做真实工单、实时聊天、OCR、文件上传、短信通知或自动计费。
- 律师联系方式仅在客户同意后收集。
- 咨询记录列表默认对联系方式脱敏。
