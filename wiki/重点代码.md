# LawMind 重点代码

本文档按“客户发来一条消息后发生了什么”来组织，建议按以下顺序阅读：

1. `backend/api/law_routes.py`：对外 `/law/chat`
2. `backend/core/law_domain.py`：法律领域、实体、风险规则
3. `backend/core/intent_recognizer.py`：`LawIntentRecognizer`
4. `backend/agents/agent_orchestrator.py`：4 类 Agent、路由、升级
5. `backend/agents/tools.py`：法律工具
6. `backend/services/faq_sync_service.py`：FAQ -> ChromaDB
7. `backend/memory/conversation_memory.py`：三层记忆
8. `backend/mcp/knowledge_base.py`：ChromaDB 知识库

## 1. `/law/chat` 主链路

核心文件：`backend/api/law_routes.py`

处理顺序：

```text
POST /api/law/chat
  -> 生成 conversation_id / session_token / user_id
  -> MemoryManager.get_context()
  -> LawIntentRecognizer.recognize()
  -> Request(...)
  -> AgentOrchestrator.run()
  -> 读取 result.response
  -> 追加“不构成正式法律意见”
  -> 组装 LawChatPublicResponse
```

关键设计：

- `user_id` 由 `LAWMIND_SESSION_SECRET` 派生，不接收客户任意指定。
- `session_token` 由服务端生成，数据库只保存哈希。
- 对外响应是白名单模型，不返回内部 Agent/Tool 信息。
- 公开字段包含 `escalated`。

## 2. 法律领域模型

核心文件：`backend/core/law_domain.py`

```python
class LawIntent(str, Enum):
```


```text

disputed_amount

risk_flags
```

## 3. 路由决策

核心文件：`backend/agents/agent_orchestrator.py`

```text
if CRITICAL or DETENTION or COURT_SOON:
    -> EscalationAgent
elif LAWYER_APPOINTMENT:
    -> EscalationAgent
elif criminal intent:
    -> CriminalDefenseAgent
elif civil intent:
    -> CivilConsultationAgent
else:
    -> ReceptionAgent
```

`_domain_scores()` 会根据法律意图、关键词、风险信号和实体为 Agent 打分，并决定主 Agent 与辅助 Agent。

## 4. Agent 与工具边界

每个 Agent 有自己的 `AgentProfile`：

```text
ReceptionAgent:
  tools = search_law_knowledge + identify_legal_domain
         + check_missing_facts + build_reception_summary

CriminalDefenseAgent:
  tools = search_law_knowledge + extract_criminal_facts
         + check_criminal_stage + assess_criminal_risk

CivilConsultationAgent:
  tools = search_law_knowledge + extract_civil_facts
         + determine_procedure + assess_civil_risk

EscalationAgent:
  tools = recommend_lawyer + validate_contact
         + create_consultation_record + build_handoff_summary
```

这就是“不同 Agent 可以用不同工具”的实现方式。

## 5. FAQ 同步

核心文件：`backend/services/faq_sync_service.py`

```text
PostgreSQL Faq
  -> normalize
  -> KnowledgeBase.add_documents()
  -> delete old vector (if needed)
  -> mark_synced / mark_failed
```

工作人员新增 FAQ 后会立即创建 `sync_status = pending`，同步成功后变为 `synced`；失败时记录错误但不会阻塞主链路。

## 6. 三层记忆

核心文件：`backend/memory/conversation_memory.py`

```text
Redis
  -> 当前会话最近消息
  -> 超过阈值压缩为摘要

ChromaDB episodic
  -> 历史摘要

ChromaDB user_profile
  -> 用户画像
```

同步 ChromaDB 操作放在线程池中，降低主请求链路阻塞。

## 7. 知识库

核心文件：`backend/mcp/knowledge_base.py`

```text
law_knowledge_base
  -> FAQ 同步写入
  -> 领域摘要默认写入
  -> ChromaDB 自动 embedding
  -> query 语义检索
```

## 8. 建议阅读顺序

读代码时可以用“一个请求”串起来：

```text
用户消息
  -> law_routes.py
  -> law_domain.py / intent_recognizer.py
  -> agent_orchestrator.py
  -> tools.py
  -> knowledge_base.py
  -> memory/conversation_memory.py
  -> faq_sync_service.py
  -> law_routes.py 返回
```

不需要一开始读完全部代码，先看主链路，再按需深入。
