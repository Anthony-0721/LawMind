# LawMind 定位与技术亮点

## 一句话定位

LawMind 是面向中国大陆律所对外咨询场景的 **多 Agent 智能法律咨询系统**。它不是一个普通的聊天机器人，而是一条“识别法律问题 -> 检索法律知识 -> 多 Agent 分析 -> 风险提示 -> 律师推荐 / 转人工 -> 咨询记录闭环”的工程链路。

## 它解决什么问题

律所真实咨询中，客户的问题通常不是一句话就能回答的：

- “喝酒开车被查到，会怎么样？”
- “家人被刑事拘留了，还能取保吗？”
- “对方欠钱不还，诉讼时效过了吗？”
- “交通事故已经发生了，怎么计算赔偿？”
- “我该预约律师，还是先自己准备材料？”

如果只用一个模型直接回答，会出现三类问题：

1. **领域判断不准**：刑事问题、民事问题、律所服务问题混在一起。
2. **只答通用内容**：客户缺少关键事实时，系统直接给结论，甚至产生错误承诺。
3. **无法形成业务闭环**：客户咨询后没有咨询记录、没有律师推荐、没有人工跟进入口。

LawMind 的目标是把这一条链路工程化，而不是只做一个“能说话”的模型壳子。

## 当前架构

```text
客户浏览器
  -> Nginx
  -> Vue 3 客户页 / 工作人员页
  -> FastAPI /api/law/*
  -> 法律意图与风险识别
  -> Redis 读取近期对话
  -> ChromaDB 召回法律知识
  -> AgentOrchestrator 路由
  -> LLM Agent / 工具调用
  -> PostgreSQL 保存咨询记录 / FAQ / 律师
  -> 返回白名单响应 + 免责声明
```

核心处理链路：

```text
用户消息
  -> 读取记忆
  -> 识别法律领域
  -> 提取实体与风险信号
  -> Agent 按需调用 search_law_knowledge（RAG）
  -> 生成结构化路由决策
  -> 主 Agent / 辅助 Agent / 升级 Agent
  -> Skills 注入
  -> 工具调用
  -> 初步法律分析
  -> 律师推荐、留资或转人工
  -> 写回记忆
  -> 监控与评测
```

## 4 类 Agent

| Agent | 职责 | 覆盖领域 |
| --- | --- | --- |
| ReceptionAgent | 律所接待、领域识别、缺失事实追问 | 律所服务、收费、流程、暂不明确 |
| CriminalDefenseAgent | 刑事风险、案件阶段、拘留/取保/起诉 | 醉驾/危险驾驶、刑事辩护 |
| CivilConsultationAgent | 民事程序、证据、责任与风险 | 劳动争议、婚姻家事、合同纠纷、交通事故、民间借贷 |
| EscalationAgent | 转人工、预约律师、留资、交接摘要 | 紧急风险、预约律师 |

当前不是“一个领域一个 Agent”，而是按法律能力边界划分为 4 类。

## 和普通 Chatbot 的区别

```text
普通 Chatbot：
用户输入 -> 大模型直接回答

LawMind：
用户输入
  -> 意图识别
  -> 风险识别
  -> 记忆读取
  -> 知识检索
  -> 结构化路由
  -> 工具调用
  -> 初步分析
  -> 律师推荐 / 转人工
  -> 咨询记录
  -> 监控与评测
```

LawMind 更接近一个 **Law Agent Runtime**，而不仅是对话界面。

## 为什么这个设计有价值

- **法律领域复杂**：刑事、民事、程序、证据、时效、风险等需要不同处理方式。
- **不能盲目承诺**：所有对外回复必须保留“不构成正式法律意见”。
- **需要业务闭环**：不是聊完就结束，而是形成咨询记录、律师推荐、人工跟进。
- **需要可运维**：FAQ、律师、知识库都要由工作人员可管理，而不是写死代码。
