# LawMind 扩展方向

## 当前边界

LawMind 当前已经完成：

- 法律咨询对话
- 7 类法律领域 + 风险识别
- 4 类 Agent
- RAG 知识库
- 律师推荐
- 留资/转人工
- PostgreSQL / Redis / ChromaDB
- 工作人员管理页
- FAQ / 律师 CRUD
- 免责声明和安全边界
- 评测与测试

但以下能力当前没有实现：

- 文件/合同上传
- PDF/图片 OCR
- 真实实时聊天（WebSocket）
- 真实工单系统
- 短信/邮件/微信通知
- 自动排期与律师日程
- 多律所租户
- 自动收费/支付
- 真实执业律师审核工作流
- 地方性法规知识库
- 更完整的 Long-term Memory 数据清洗
- 完整 RAG rerank/embedding 模型升级

## 下一阶段建议

### 1. 案件材料接入

支持客户上传合同、判决书、事故认定书、借条等文件，自动提取关键事实并生成结构化摘要：

```text
上传材料
  -> OCR / 文本抽取
  -> 识别当事人、金额、时间、条款
  -> 生成 case brief
  -> 转入专业 Agent 分析
```

### 2. 真实人工衔接

当前转人工是“留资 + 记录”，下一步可以接：

- 企业微信/钉钉/短信通知
- 工单排队
- 律师自动分配
- 预约时间确认
- 跟进状态流转

### 3. 律师工作台

工作人员页可以扩展：

- 案件管理
- 律师排期
- 客户标签
- 聊天记录导出
- 合同模板
- 收费与账期
- 客户跟进提醒

### 4. 知识库持续化

- 增加地方性法规、司法解释、典型案例。
- 对官方法条做版本管理。
- 支持法条生效日期、废止日期。
- 增加来源链接和人工复核状态。

### 5. 多租户

如果面向多个律所：

```text
lawyer_firm_id
staff_account
tenant knowledge base
tenant FAQ
tenant lawyer
tenant consultation
```

### 6. 评测增强

```text
真实标注集
意图 Accuracy / Macro-F1
RAG 召回率
回答相关性
法律信息准确性
人工律师复核
```

## 技术演进建议

- 将 `LawIntentRecognizer` 的规则、向量和 LLM 三路融合继续保留，同时增加可配置权重。
- 将 `AgentProfile` 从代码常量逐步改为配置/数据库。
- 将 FAQ / domain brief / 合同 / 案例统一纳入知识库元数据。
- 为 `sync_status` 增加失败重试和异步队列。
- 对 `escalated` 增加原因字段和持久化事件。
- 对外接口继续维持白名单，避免逐步退回“全量内部字段外露”。

## 一句话

LawMind 当前已经完成“从通用多 Agent 客服到垂直法律行业”的场景化闭环；下一步重点是 **真实业务接入、案件材料处理、律师工作流和多租户落地**。
